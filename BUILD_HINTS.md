# Сборка и отладка: как решать проблемы

Этот файл поможет, если сборка или запуск плагина вызывают ошибки.

> Совет: не копируй решения механически. Постарайся понять, почему возникла проблема — это поможет в будущем

---

## Если что-то не работает: общий подход

1. Прочитай текст ошибки внимательно. Часто ответ уже там.
2. Проверь, на что указывает ошибка: файл, строку, модуль.
3. Подумай: что менял перед появлением ошибки?
4. Попробуй воспроизвести проблему на минимальном примере.

## Частые ситуации

### Не найдены модули: `Cannot find module 'esbuild'`

**Что происходит**: Зависимости проекта не установлены.

**Как проверить**:
```bash
ls node_modules  # если папки нет или пустая — нужно установить
```

**Решение**:
```bash
npm install
```

---

### Ошибка в JSON: `Unexpected token } in JSON at position XXX`

**Что происходит**: В `prompts.json` нарушен синтаксис.

**Как найти проблему**:
- Открой файл в редакторе с подсветкой синтаксиса
- Перейди к указанной позиции или ищи визуально:
  - Незакрытые кавычки
  - Лишние запятые после последнего элемента
  - Пропущенные запятые между элементами

**Примеры**:
```json
// Лишняя запятая в конце
{
  "key": "value",
}

// ✅ Правильно
{
  "key": "value"
}
```

**Инструменты**: [JSONLint](https://jsonlint.com) поможет проверить файл.

---

### Не находится файл: `Cannot resolve '../../prompts.json'`

**Что происходит**: Путь к файлу указан неверно.

**Как проверить**:
1. Где лежит `prompts.json`? (должен быть в корне проекта)
2. Откуда идёт импорт? (`src/ai/prompts.js`)
3. Сколько уровней нужно подняться: `src/ai/` → `src/` → `/` = `../../`

**Решение**: Убедись, что путь в импорте соответствует реальной структуре:
```javascript
// Если prompts.json в корне проекта:
const promptsConfig = require('../../prompts.json');
```

---

### Ошибка синтаксиса в JavaScript: `Unexpected ","`

**Что происходит**: В коде пропущен аргумент, лишняя запятая или другая синтаксическая ошибка.

**Как найти**:
1. Esbuild укажет файл и строку: `src/settings/tab.js:52:24`
2. Открой файл, посмотри на указанную строку и соседние
3. Проверь:
   - Все ли аргументы функций на месте
   - Нет ли лишних или пропущенных запятых
   - Правильно ли закрыты скобки

**Пример**:
```javascript
// Пропущен второй аргумент
.setLimits(256, , 256)

// Три аргумента: мин, макс, шаг
.setLimits(256, 4096, 256)
```

---

### Ошибка импорта: `Cannot read properties of undefined`

**Что происходит**: Модуль импортирован не так, как экспортирован.

**Как понять разницу**:

| Как экспортировано | Как импортировать |
|-------------------|------------------|
| `module.exports = { A, B }` | `const mod = require('./file')` → `mod.A` |
| `module.exports = { A, B }` | `const { A, B } = require('./file')` |
| `exports.A = A` | `const { A } = require('./file')` |

**Как проверить**: Открой файл, который импортируешь, и посмотри на последнюю строку — что там в `module.exports`.

## Платформенные особенности

### Windows

- Используй прямые слеши `/` в путях, даже если система показывает `\`
- Если `npm run dev` не отслеживает изменения, попробуй `npm run build` вручную
- Запускай терминал с правами, достаточными для записи в папку проекта

### macOS

- Если `npm install` зависает, попробуй:
  ```bash
  npm cache clean --force
  npm install
  ```
- Если изменения не видны в Obsidian, перезагрузи приложение: `Cmd+P` → `Reload app without saving`

### Linux

- Если `npm` не установлен:
  ```bash
  # Debian/Ubuntu
  sudo apt install nodejs npm
  ```
- При проблемах с правами: настрой npm на установку без sudo или используй `nvm`

## Git: если пуш не работает

### `Updates were rejected because the remote contains work that you do not have locally`

**Что происходит**: На сервере есть изменения, которых нет у тебя локально.

**Решение**:
```bash
# Забрать изменения с сервера
git pull origin main

# Если возник конфликт — отредактируй файлы, удали метки <<<<<<<, =======, >>>>>>>
# Затем:
git add <файлы>
git commit -m "Resolve conflicts"
git push origin main
```

### `fatal: Need to specify how to reconcile divergent branches`

**Что происходит**: Ветки расходятся, Git не знает, как их объединить.

**Решение**:
```bash
# Использовать rebase (история будет линейной)
git pull --rebase origin main

# Или настроить по умолчанию для будущих операций
git config pull.rebase true
```

## Плагин не работает в Obsidian

### Плагина нет в списке

**Проверь**:
- Файлы `main.js`, `manifest.json`, `prompts.json` лежат в `.obsidian/plugins/ai-assist/`
- Поле `id` в `manifest.json` совпадает с именем папки
- В настройках Obsidian отключён "Безопасный режим"

### Ошибка при загрузке

1. Открой консоль разработчика: `Ctrl+Shift+I` (Windows/Linux) или `Cmd+Option+I` (macOS)
2. Перейди во вкладку Console
3. Найди красные ошибки, связанные с твоим плагином
4. Скопируй текст ошибки и поищи решение

### Изменения не применяются

**Порядок действий**:
1. Убедись, что сборка прошла без ошибок: `npm run build`
2. Скопируй обновлённые файлы в папку плагина
3. Перезагрузи плагин в Obsidian: выключи и включи в настройках
4. Если не помогло — перезапусти само приложение Obsidian

## Полезные команды

```bash
# Сборка в режиме разработки (с авто-пересборкой)
npm run dev

# Продакшен-сборка
npm run build

# Проверить устаревшие зависимости
npm outdated

# Переустановить зависимости с нуля
rm -rf node_modules package-lock.json
npm install

# Проверить JSON-файл на валидность
node -e "JSON.parse(require('fs').readFileSync('prompts.json'))" && echo "OK"

# Найти использование функции в коде
grep -r "имя_функции" src/
```

## Если ничего не помогло

1. Скопируй полный текст ошибки
2. Запиши:
   - Операционная система
   - Версия Node.js (`node -v`)
   - Что делал перед появлением ошибки
   - Что ожидал получить, что получил вместо этого
3. Поищи решение по тексту ошибки в интернете
4. Если не нашёл — опиши проблему в [Issue](https://github.com/ripidipi/Obsidian-plugin/issues)

> Помни: большинство проблем решаются проверкой очевидного — сохранён ли файл, установлен ли пакет, перезагружен ли плагин. Не спеши, проверяй по порядку
